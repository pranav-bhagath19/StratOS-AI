# StratOS-AI — Failure Matrix (`FAILURE_MATRIX.md`)

| Component | Failure | Trigger | Observable Symptom | Root Cause | Severity | Recommended Fix |
|---|---|---|---|---|---|---|
| **LLM Invocation Layer** (`base/llm.py`) | Fail-Fast Crash on 5xx / Timeout / Overloaded | Upstream provider returns 503 (e.g. Nvidia overloaded), 502, 500, or times out (>45s) | Pipeline crashes instantly; `Analysis failed: ...`; no brief produced | `llm.py` line 78 only checks for HTTP 429 (`is_rate_limit`). Any 5xx or timeout is treated as a fatal non-retryable error, immediately raising and terminating model rotation | **P0** | Expand fallback loop in `llm.py` to catch 503, 502, 500, 504, `TimeoutError`, and `httpx.TimeoutException` to try next model |
| **LLM Invocation Layer** (`base/llm.py`) | Exhaustion of Shared Upstream Rate Limits | Calling public free-tier models (`:free`) during peak traffic | `Model ... hit rate limit (429). Falling back...` across all models until `All configured models returned 429` crash | `llm.py` ignores `settings.openrouter_model` and hardcodes `openrouter_free_models` which use a shared global rate-limit pool on OpenRouter | **P0** | Respect `settings.openrouter_model` from `.env` when `OPENROUTER_API_KEY` is provided; allow paid models with dedicated quota |
| **All Agents** (`planner`, `scout`, `verifier`, `coordinator`) | Missing Try/Except on LLM Invocations | Any exception thrown by `get_llm_response` | Entire LangGraph workflow halts immediately; status set to failed | None of the agent runners wrap `get_llm_response` in try/except; they only wrap `extract_json` | **P0** | Wrap `get_llm_response` in try/except in all four agents, falling back to deterministic heuristic steps/challenges/brief |
| **Browser Tool** (`tools/browser/playwright.py`) | Process Hang / Thread Deadlock on Windows | Multi-threaded invocation of `sync_playwright` during parallel researcher execution | Researcher hangs indefinitely (or until 160s timeout); worker thread blocked forever | `sync_playwright` on Windows is not thread-safe. Exiting `with sync_playwright() as p:` calls `p.stop()`, which hangs waiting for driver IPC pipe closure in worker threads | **P0** | Switch to native `async_playwright` on the event loop, or isolate browser execution behind a single-worker lock / subprocess |
| **Frontend UI** (`dashboard/page.tsx`) | False Success & Masked Backend Failure | Backend fails in `_run_analysis` and emits SSE done | UI displays "COMPLETE" in green/neutral, log shows "ANALYSIS COMPLETE", but brief area is completely blank | SSE listener handles `event: done` by setting `setPhase("complete")` unconditionally without checking if `data.brief` is null or if a failed event was received | **P0** | Inspect incoming SSE event types: if `failed` event received or `brief === null`, transition to `phase = "failed"` and render clear error banner |
| **Researcher Tools** (`tools/manager.py`) | Concurrent Search Rate Limiting on DuckDuckGo | Parallel execution of 3+ search steps (`serp_search`, `serp_news`, `mcp_search`) | DuckDuckGo returns 202 / RateLimit; all 3 search steps return empty after retries | `DuckDuckGoSearchProvider` receives 3 concurrent calls from the same client IP with exponential backoffs that collide | **P1** | Add an `asyncio.Semaphore(1)` around search calls to serialize DDG queries and insert a small 500ms delay |
| **Database / Cache** (`database/firebase/admin.py`) | Concurrent SDK Initialization Collision | Parallel cache lookups at startup in Researcher | `ValueError: The default Firebase app already exists` and `Cache: DB lookup failed` | `get_firebase_app()` checks `if _app is None` without a mutex lock; concurrent asyncio threads both initialize the app | **P1** | Add a `threading.Lock()` or check `firebase_admin._apps` before calling `initialize_app` |
| **Researcher Tools** (`agents/researcher/agent.py`) | LinkedIn Scraping Authwall Block | Planner generates `scraper_linkedin` step with `https://linkedin.com/in/...` | Step returns 0 bytes or authwall redirect; status marked `empty` | LinkedIn blocks automated scrapers without session cookies or Bright Data Web Scraper API credentials | **P1** | Replace direct Playwright scraping of LinkedIn with public search querying (e.g. `site:linkedin.com/in/ "{name}"`) |
| **Scout & Verifier** (`scout/agent.py`, `verifier/agent.py`) | Context Truncation & State Evidence Loss | Researcher gathers >6000 characters of rich web evidence | Evidence gathered by steps 3, 4, 5 is truncated and ignored | Slicing `findings[:6000]` in Scout and `findings[:4500]` in Verifier discards majority of findings | **P1** | Structured chunking / map-reduce over step findings or increase context window slice to 20,000+ characters |
| **Verifier Agent** (`verifier/agent.py`) | Unverified / Fabricated Confidence Scores | Verifier LLM output generation | Arbitrary confidence score assigned with no source check; defaults to 60 | Verifier does not verify sources against primary evidence; confidence score is generated by LLM prompt heuristics | **P1** | Calculate confidence score algorithmically from corroborating sources count, domain authority, and freshness |
| **Database Repositories** (`repositories/base.py`) | Desynchronized Local DB Files | Running backend from `backend/` vs running tests/scripts from repo root | Stored analyses, events, and briefs vanish depending on launch directory | `LOCAL_DB_FILE = "firebase_local.json"` uses a relative path instead of repo root absolute path | **P2** | Anchor `LOCAL_DB_FILE` to `Path(__file__).resolve().parents[2] / "firebase_local.json"` |
| **Database Repositories** (`repositories/base.py`) | JSON File Corruption from Concurrent Writes | Multiple concurrent events written to `firebase_local.json` | `JSONDecodeError: Extra data` or `Unterminated string` | `_load_local_db` and `_save_local_db` perform non-atomic read-modify-write cycles without file locks | **P2** | Add file-level locking (`portalocker` / `msvcrt`) or in-memory async write queue |
